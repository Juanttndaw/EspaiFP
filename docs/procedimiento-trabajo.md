# Procedimiento de trabajo — EspaiFP

## Organización de tareas

Las actividades se identificarán con códigos T01–T17 y se controlarán con los estados **Pendiente**, **En proceso** y **Completada**. La revisión del progreso se realizará al menos una vez por semana.

## Control de versiones

- La rama `main` contendrá las versiones estables.
- Se podrán crear ramas descriptivas para nuevas funcionalidades, por ejemplo `feature/login` o `feature/reservas`.
- Los cambios se integrarán en `main` después de comprobar su funcionamiento.
- Se realizarán commits al terminar una tarea o un avance funcional significativo.
- Los mensajes serán breves y descriptivos, por ejemplo `feat: añadir consulta de aulas` o `fix: corregir validación de horarios`.

## Incidencias y finalización

Los errores se anotarán indicando el problema, la parte afectada, los pasos para reproducirlo y la solución aplicada. Se podrán registrar mediante GitHub Issues.

Una tarea se considerará terminada cuando alcance el resultado esperado y se haya comprobado su funcionamiento básico.

## Copias de seguridad y seguridad

El repositorio remoto de GitHub servirá como copia del historial del código. Se mantendrá también una copia local de la documentación y se realizarán copias adicionales antes de cambios importantes. No se subirán contraseñas, tokens, claves privadas ni datos personales reales.
